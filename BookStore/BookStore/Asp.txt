HttpResponse

 - Middleware (промежуточное ПО) — это компонент, который обрабатывает HTTP-запрос на пути от клиента к серверу и обратно.
 
 - Все данные запроса передаются в middleware через объект Microsoft.AspNetCore.Http.HttpContext. Этот объект инкапсулирует информацию о запросе, позволяет управлять ответом и, кроме того, имеет еще много другой функциональности.
 
 - HttpContext используется на всём пути обработки запроса — от первого middleware до контроллера и обратно — и позволяет каждому этапу обработки видеть и при необходимости изменять как запрос, так и ответ.
 
HttpRequest
 
 - HttpRequest — это объект, который содержит всю информацию о запросе, пришедшем от клиента на сервер.
 
Controller

 - Controller — это специальный класс, который отвечает за обработку HTTP-запросов и возврат ответа клиенту.
 
Куда приходят данные

 - Если данные в URL (?id=5 или /user/5), они попадают в обычные параметры (например, int id)
 
 - Если данные в теле запроса (например, JSON), они приходят в объект с [FromBody]
 
  - Обмен данными произовдится при помощи Http протокола.
  
  - В обмен данных входит обьязательно запрос и ответ,как в принципе работает телефон.
  
  - Запрос(Request) состоит из : 
  
  - Protocol(Http/Https) - Http от Https отличается сертификатом безопасности,Https при передаче данных шифрует данные сертификатом безопасности.
  - Host
  - Port
  - Route
  - Methods
 
  - Body
  - Headers
  - Query params - для передаче Query params ставится знак вопроса после Route,и параметры передаются как названия_параметра=значение_параметра.Если параметра нету,то между ними ставится знак &. Пример ?limit=10&skip=0
  
 Примеры
 http://localhost:5151/task
 Protocol -  http://
 Host - localhost
 Port - 5151
 Route - task
 Query params - тут нету
 
 Для того чтобы получить Body,Headers,Query params используется специальные атрибуты [FromBody],[FromHeader(Name="Content-Type")],[FromQuery].
 
 
 Рефлексия представляет собой процесс выявления типов во время выполнения приложения. 
 Каждое приложение содержит набор используемых классов, интерфейсов, а также их методов, свойств и прочих кирпичиков, из которых складывается приложение. 
 И рефлексия как раз и позволяет определить все эти составные элементы приложения. То есть основная задача рефлексии - это исследование типов.
 
 Основной функционал рефлексии сосредоточен в пространстве имен System.Reflection. В нем мы можем выделить следующие основные классы:
  
  - Assembly: класс, представляющий сборку и позволяющий манипулировать этой сборкой
  - AssemblyName: класс, хранящий информацию о сборке
  - MemberInfo: базовый абстрактный класс, определяющий общий функционал для классов EventInfo, FieldInfo, MethodInfo и PropertyInfo
  - EventInfo: класс, хранящий информацию о событии
  - FieldInfo: хранит информацию об определенном поле типа
  - MethodInfo: хранит информацию об определенном методе
  - PropertyInfo: хранит информацию о свойстве
  - ConstructorInfo: класс, представляющий конструктор
  - Module: класс, позволяющий получить доступ к определенному модулю внутри сборки
  - ParameterInfo: класс, хранящий информацию о параметре метода
  
  🔧 Что такое динамическая загрузка сборок?
  
  Это когда программа сама загружает DLL (сборку) во время своей работы, а не во время компиляции.
  
  using System.Reflection;
  
  // Загружаем сборку (DLL) из файла MyApp.dll
  Assembly asm = Assembly.LoadFrom("MyApp.dll");
  
  // Выводим полное имя сборки (включает название, версию, культуру и публичный ключ)
  Console.WriteLine(asm.FullName);
  
  // Получаем все типы (классы, структуры, интерфейсы и т.д.), определённые в сборке MyApp.dll
  Type[] types = asm.GetTypes();
  
  // Перебираем все типы и выводим только их имена (без пространства имён)
  foreach (Type t in types)
  {
      Console.WriteLine(t.Name);
  }

  ➡ Программа сама открывает внешний .dll файл прямо в момент выполнения, как будто читает модуль "на лету".
  
  🕓 Что такое позднее связывание (late binding)?
  
  Это когда ты не знаешь заранее, какие классы и методы есть в сборке, и узнаёшь это во время работы программы.
  
  Type? type = asm.GetType("MyLibrary.Calculator");
  
  MethodInfo? method = type?.GetMethod("Add");
  
  object? result = method?.Invoke(null, new object[] { 2, 3 });

  ➡ Ты не подключал MyLibrary.dll в проект напрямую, но вызываешь её метод Add.
  
 Атрибуты в .NET
 
 Атрибут простыми словами — это "ярлычок" или "пометка", которую ты вешаешь на класс, метод или свойство, чтобы сообщить программе какую-то дополнительную информацию.

 Dependency Injection (DI) — це підхід у програмуванні, при якому об’єкт (клас) не створює сам свої залежності, а отримує їх ззовні (через конструктор, метод або властивість).
 
 Мета DI:
 
 Зменшити зв’язність коду — клас не прив’язаний до конкретних реалізацій.
 
 Спростити заміну залежностей — можна легко підставити іншу реалізацію без зміни коду класу.
 
 Полегшити тестування — у тести можна передавати фейкові чи мок-об’єкти.
 
 📌 Простими словами: Dependency Injection — це коли ми даємо класу готові “інструменти” для роботи, а він не шукає їх сам.
